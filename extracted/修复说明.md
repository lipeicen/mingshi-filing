## 〇-4、数据库导入支持（2026-11-20 追加）

案件数据现在可以存入 MySQL 统一管理，工具用 `--from-db` 直接读取待立案案件：

1. **建表脚本** `db/schema.sql`：`cases`（案件主表）/ `agents`（代理人）/ `case_files`（材料）/ `system_config` / `system_users` 五张表，列名与既有部署库结构一致（`applicant_nature`=当事人类型、`applicant_uscc`=统一社会信用代码、`applicant_cert_no`=法定代表人证件号码、`applicant_reg_address`=注册地）。
2. **导入脚本** `import_cases_to_db.py`：把 JSON 案件数据写入数据库。`--init-schema` 建库建表并为既有 `cases` 表自动补齐缺失列（不动已有数据）；按 `case_no` 幂等导入（重复导入=更新，不产生重复案件）；`--sync-account` 把法院账号同步到 `system_users`。
3. **加载链路** `test_filing_flow.py --from-db`：原来只支持自然人原告/被告的简单字段，现已扩展——法人字段（当事人类型、法定代表人及其证件号、注册地）和 `agents` 表代理人均能完整还原；自然人证件号读取 `applicant_id`，法人自动回退读取 `applicant_uscc`；代理人的「被代理人」默认为该案原告。
4. **配置**：数据库连接走环境变量（`.env` 中 `DB_HOST/DB_USER/DB_PASSWORD/DB_NAME/DB_PORT`），与原有 `src/config/db_config.py` 一致。
5. **派生字段自动回填**：导入时自动从身份证号推导 `applicant_birth/age/gender`、`respondent_birth/age/gender`（年龄按导入当天计算）以及 `agents.agent_gender`；法人的统一社会信用代码不触发推导。已验证：3 个自然人原告、4 个被告、4 条代理人记录全部回填正确。

使用方式：

```bash
pip install pymysql
python import_cases_to_db.py --init-schema --sync-account   # 首次：建表+导入+同步账号
python import_cases_to_db.py --data-file <你的案件.json>     # 日常导入新案件
python test_filing_flow.py --from-db --visual               # 从数据库读取待立案案件并立案
```

验证结果（本机 MySQL 8.0，库 court_filing_civil）：4 个测试案件（含法人原告案）全部导入成功；重复导入幂等更新；`--from-db` 真实读取 9 条待立案案件，4 个新案件的案由、法人字段、代理人（含执业证号、被代理人）、材料路径全部正确还原；离线往返测试 `tests/test_db_roundtrip.py` 4/4 通过。

**数据库端到端真实网站验证（2026-11-20）**：新建 4 条案件数据 `test_data/test_cases_db_e2e.json`（身份证/统一社会信用代码均带合法校验位，覆盖买卖合同/民间借贷/交通事故/服务合同 4 类案由，含**法人被告**与**双代理人**两种新场景），导入数据库后用 `python test_filing_flow.py --from-db --db-case-nos ... --visual` 从数据库读取并跑真实网站（DRY RUN）：4/4 全部通过——法人被告的「证照类型」精确选中「统一社会信用代码证」、双代理人案件预览自检 `yg:1 bg:1 dlr:2`、全部案件案由正确、预览页当事人完整、未真实提交。新增 `--db-case-nos` 参数可按案件编号有选择地跑数据库中的案件。

## 二、核心修复明细

### 1. 案由下拉框卡住

页面案由控件是 uni-app `uni-data-tree` 级联选择器，搜索框只在弹层打开后渲染。原代码先找搜索框，导致始终报 `no input`，流程停在「选择立案案由」。

已新增并使用 `_select_cause_from_tree`：

- 点击 `.uni-data-tree-input` 打开弹层；
- 在 `.uni-data-tree-dialog` 内填写搜索关键词；
- 精确匹配并点击案由选项；
- 支持级联展开和多次重试；
- 选中后校验占位符已变为案由名称。

真实环境日志确认：`案由选择成功: 买卖合同纠纷`。

### 2. 当事人下拉框误点只读卡片

已保存的当事人卡片与编辑表单使用相同的字段标签（如「证件类型」），但没有可操作控件。原代码按标签查找时，容易点到已保存卡片的只读行，导致被告性别、证件类型等下拉框无法打开。

已修复：

- `_js_click_dropdown_trigger` 只点击包含真实输入、选择器或下拉控件的表单项；
- 自动跳过只读展示卡片；
- 下拉检测逻辑继续扫描后续表单项，不再遇到只读行就提前结束；
- 证件类型复核和重选统一使用已验证可用的下拉助手。

真实环境确认：原告、被告均显示 `居民身份证`，被告保存成功。

### 3. 代理人表单提前关闭

`_set_agent_represented` 在勾选「被代理人」前会调用 `_sync_party_store`，其中 `ryxx.init()` 会重置 `showForm/formEdit`，把当前打开的代理人编辑表单直接关闭。结果是后续找不到保存按钮，只能走本地 Vue 数据兜底，不能真实保存到服务端。

已修复：

- 编辑表单打开期间跳过 `ryxx.init()`；
- 仅刷新当事人选项列表，不重置当前表单；
- 「被代理人」点击限定在代理人编辑表单内，避免误点已保存的原告卡片。

真实环境日志确认：`设置被代理人 #1: {'ok': True, 'method': 'scoped-checkbox', 'text': '测试原告甲'}`。

### 4. 代理人真实保存

本次补齐了代理人保存所需的字段映射和校验：

- `license_no` 正确映射到「代理人执业证号」；
- `work_unit` 正确映射到「单位」；
- `agent_type` 使用页面合法选项（如「执业律师」），不再把「特别授权」误当作代理人类型；
- 保存时优先点击页面真实「保存」按钮；
- 如出现 `不能为空` 等表单校验错误，停止本地数据注入兜底并返回明确错误，避免把未保存的数据误判为成功。

真实环境日志确认：代理人保存后页面提示 `保存成功`，保存方法为 `smart-save-early`，未再走 `direct-vue-data`。

### 5. 旧代理人服务端清理

原删除逻辑按全局文本查找「删除」，可能点到其他区块，或只删除页面本地状态而未同步服务端，导致每次测试后预览页多出一个旧代理人。

已新增 `_delete_existing_agents_vue`：

- 调用页面自身 `ryxx.delRyxx(item, 'dlr')`；
- 自动确认删除弹窗；
- 走页面原有服务端 DELETE API；
- 删除后读取 `sessionStorage.layyInfo` 验证剩余数量。

真实环境日志确认：`{'ok': True, 'attempted': 1, 'deleted': 1, 'remaining': 0}`。

### 6. 预览页数据修复

PC 预览页的当事人区块由 `detail` 组件按 `list.yg/list.bg/list.dsr` 渲染，而服务端草稿保存在 `layyInfo.dsrs/dlrs` 中。原代码把数据写入了错误结构，导致预览页空白或显示旧数据。

已修复：

- 从 `layyInfo` 读取真实服务端草稿；
- 按 `ssdw` 编码把当事人映射到 `yg/bg/dsr`；
- 同步 `list/dsrs/dlrs` 并触发 Vue 更新；
- 移除了旧的、针对测试数据硬编码的预览 DOM 修补逻辑。

真实环境预览页已显示：

### 7. 自然人派生字段补齐（出生日期/年龄/工作单位/职务）

问题：预览页原告缺「职务」，被告缺「出生日期」「年龄」。

根因有三个：

1. 站点只在证件号发生**真实输入变化**时才通过 `zjhm` 输入监听派生 `csrq`(出生日期)、`nl`(年龄)、`xb`(性别)；草稿回填或 JS 赋值后证件号未变化时不会触发，导致保存到服务端的当事人缺出生日期和年龄。
2. 职务显示名 `zyMc` 由 `codeList.zy` 按职务代码反查。页面职务选项中没有独立的「其他」，原代码默认选择裸「其他」，保存后 `zyMc` 为空，预览页职务栏空白。
3. 补齐 `csrq` 后，站点 watcher 可能把日期串覆盖进 `nl`，触发「年龄不能超过3个字符」的服务端/表单校验，导致保存失败（被告曾因此未保存成功）。

已修复：

- 职务默认值由「其他」改为页面已验证可保存的完整选项「其他办事人员和有关人员」；
- 新增 `_ensure_party_derived_fields`：在填写完成后与点击保存前各执行一次，定位当前打开的 `addSscyr` 编辑表单，按 18 位身份证号派生 `csrq`(YYYY-MM-DD) 与 `nl`(1-3 位数字字符串)，补齐 `gzdw`(工作单位)、`zyMc`(按 `codeList.zy` 反查)，并同步到 `addSscyr` 的 `ryxx` 属性与 `ryxx` 组件当前编辑对象；
- 保存前校正会把不符合 `^\d{1,3}$` 的年龄重新派生，避免 watcher 覆盖导致的校验失败；
- 预览页数据修复中对自然人做兜底补齐（`csrq/nl/gzdw/zyMc`），即使个别字段保存异常预览也能完整显示。

真实环境日志确认：

- 原告 `patched: {}`（站点已自行派生），被告 `patched: {'csrq': '1994-03-06', 'nl': '32'}`；
- 被告真实 UI 保存成功（`smart-save-early`），预览页原告、被告的出生日期、年龄、工作单位、职务四项全部完整显示。

### 8. 案由级联选择器增加等待与重试

问题：页面加载较慢时，`.uni-data-tree` 尚未渲染完成就执行级联选择，导致未命中并回退到不可靠的旧版搜索流程，后续步骤全部错位。

## 四、安全与使用说明

1. 压缩包不包含真实账号、密码或 `auth_state.json`。
2. 请复制 `src/.env.example` 为根目录 `.env`，填写自己的账号和密码。
3. 首次正式运行前保持 `COURT_FILING_DRY_RUN=true`，确认预览页无误后再关闭。
4. 代理人数据必须提供真实有效的 `license_no`、`work_unit`、`agent_type` 和 `represented_party`。
5. `特别授权/一般授权`属于代理权限，不是本页面的「代理人类型」；代理人类型应使用「执业律师」「基层法律服务工作者」等页面选项。
